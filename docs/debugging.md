## 1. Where things are

| What | Location |
|------|----------|
| Data directory | Linux `~/.local/share/memonbooks/`; Windows `%APPDATA%\MemonBooks\MemonBooks\data\`; macOS `~/Library/Application Support/com.MemonBooks.MemonBooks/` |
| Database | `<data dir>/memonbooks.sqlite3` |
| Log | `<data dir>/logs/memonbooks.log` |
| Exports | `<data dir>/exports/` |
| Attachments | `<data dir>/uploads/` |
| Preferences | `<data dir>/theme_preference.txt`, `<data dir>/font_scale_preference.txt` |

The exact database path is the first thing the app logs: `database path: …`.

## 2. Logging

* Implemented with `log` + `simplelog` (`backend/core/logging.rs`). The log file is created (appended) on start.
* Level: **Debug** in `development` and `test` environments, **Info** in `production`. A terminal logger is added when the level is Debug.
* The environment comes from `MEMONBOOKS_ENV` (`production`/`prod`, `test`, `development`/`dev`; case-insensitive). Without it, debug builds are *development* and release builds are *production*.
* `RUST_LOG` is **not** used (simplelog is configured in code).

```bash
MEMONBOOKS_ENV=development cargo run --bin memonbooks     # verbose log + terminal output
MEMONBOOKS_ENV=production ./target/release/memonbooks    # quiet
tail -f ~/.local/share/memonbooks/logs/memonbooks.log     # Linux
```

```powershell
Get-Content "$env:APPDATA\MemonBooks\MemonBooks\data\logs\memonbooks.log" -Wait -Tail 50   # Windows (path per the directories crate)
```

To get a Rust backtrace for a panic: `RUST_BACKTRACE=1 cargo run --bin memonbooks`.

## 3. Build problems

| Symptom | Cause / fix |
|---------|-------------|
| `cargo run` says *could not determine which binary to run* | The package has four binaries and no `default-run`. Use `cargo run --bin memonbooks`. |
| Linux: `pkg-config … gtk+-3.0 not found` or a failure in `gdk-sys`/`gtk-sys` | `rfd` is built with the `gtk3` feature. Install the GTK 3 development package (Fedora `gtk3-devel`, Debian/Ubuntu `libgtk-3-dev`). |
| Linux: link errors for `xkbcommon`, `wayland`, `x11` | Install the corresponding `-devel` / `-dev` packages (winit/iced windowing libraries). |
| Out-of-memory or the machine freezes while compiling | Build with one job: `cargo build -j 1`; check with `cargo check -j 1`; run one test target at a time. |
| `error: package requires rustc …` | Run `rustup update stable`. `rust-toolchain.toml` pins channel `stable`. |
| Stale or odd build state | `cargo clean -p memonbooks` (cheap), or `cargo clean` (rebuilds every dependency – slow). |
| Offline build | `cargo check --offline` works only if the dependencies are already in `~/.cargo`. |
| Inside the Claude Code shell, `grep`/`find` print *claude native binary not installed* | These are shell functions wrapping the Claude binary. Use `command grep …` / `command find …`, or the `/usr/bin` versions. |

## 4. Start-up problems

`src/main.rs` uses `expect(..)` for start-up steps, so a failure panics with a message:

| Panic message | Meaning / action |
|---------------|------------------|
| `failed to resolve application configuration` | No home/data directory could be determined or created (`AppError::Config` / `Io`). Check `HOME` / `XDG_DATA_HOME`, permissions. |
| `failed to initialize logging` | The log folder/file cannot be created. |
| `failed to open database` | Path not writable, disk full, or the file is not SQLite. |
| `failed to run database migrations` | `AppError::Migration`: a migration failed, or a version is recorded under a different name (database from another build). Do not edit `schema_migrations` by hand; restore a backup or start a fresh data directory. |
| `no active user available for startup session` | All users are inactive. Fix in the database (set `users.is_active = 1`) or use a fresh data directory. |
| `failed to create default …` | First-run seeding failed (usually a read-only database). |

**Forgot the admin password / lost the first-run password:** the first-run password is in `logs/memonbooks.log` (`Password: …`) only if it was generated by this install. Otherwise: sign in as another user with `users.manage` and use *Users → reset password*, or start with a fresh data directory. Note that start-up currently opens as the first active user without a password ([security.md](security.md)).

**Wrong database opened:** compare the `database path:` log line with the file you expect; the Flatpak uses a private data directory.

## 5. Inspecting the database

Close the app (or work on a copy) and use the `sqlite3` shell:

```bash
cp ~/.local/share/memonbooks/memonbooks.sqlite3 /tmp/inspect.sqlite3
sqlite3 /tmp/inspect.sqlite3
```

```sql
SELECT version, name, applied_at FROM schema_migrations ORDER BY version;
PRAGMA foreign_key_check;                 -- should return no rows
PRAGMA integrity_check;                   -- should return 'ok'

-- ledger sanity: every posted transaction balances (amounts are TEXT decimals)
SELECT t.id, SUM(CAST(l.debit AS REAL)) AS d, SUM(CAST(l.credit AS REAL)) AS c
FROM transactions t JOIN transaction_lines l ON l.transaction_id = t.id
WHERE t.status = 'posted' GROUP BY t.id HAVING ABS(d - c) > 0.005;

SELECT * FROM audit_logs ORDER BY id DESC LIMIT 20;
```

(The `CAST … AS REAL` is for diagnosis only; the application never uses floating point for money.) Table layouts are in [database.md](database.md#6-tables). Never edit posted `transactions` / `transaction_lines` by hand; use a reversal in the app.

## 6. Using a throw-away data directory

On Linux the `directories` crate honours `XDG_DATA_HOME`, so a scratch database needs no code change:

```bash
XDG_DATA_HOME=/tmp/mb-scratch cargo run --bin memonbooks
# data lands in /tmp/mb-scratch/memonbooks/
XDG_DATA_HOME=/tmp/mb-scratch cargo run --bin seed_demo_data    # optional demo company
XDG_DATA_HOME=/tmp/mb-scratch cargo run --bin clear_demo_data
```

Windows has no equivalent override in the code; back up and move the data directory instead. Tests never use the real directory (in-memory databases).

## 7. UI problems

| Symptom | Likely cause / fix |
|---------|--------------------|
| Panic on opening a screen after a layout change, message mentions `Scrollable`, `Length::Fill` or a `debug_assert` | A widget constructor invariant (for example `Fill` on the scroll axis). Only visible when the view is built; add a view-construction test ([testing-qa.md](testing-qa.md#6-view-construction-tests-iced)). |
| Card list shows a half-cut card | A grid is using a pixel scrollable instead of `row_snap`; see [design.md](design.md#75-card-list-row-snap). |
| Text too small/large | Settings → Font Size (Small … Extra Large) multiplies with a window-width factor ([design.md](design.md#3-type-scale)). Delete `font_scale_preference.txt` to reset. |
| Wrong theme at start | Saved choice wins over OS detection. Delete `theme_preference.txt` to fall back to OS detection (done once at launch). |
| Missing icon (box glyph) | Use a constant from `icons.rs`; never a raw glyph. Check the code point exists in `lucide.ttf` (the icons unit test does). |
| Urdu/Arabic text or `₹`/`₨` shows boxes | Not supported by the bundled Pragati Narrow subset ([design.md](design.md#11-known-limitations)). |
| Window does not appear / GPU errors | iced uses wgpu. Check that Vulkan/OpenGL drivers are installed; on Wayland-only or X11-only setups make sure the matching libraries are present. Try launching from a terminal to read the error. |
| File dialog does not open on Linux | GTK3 must be installed at runtime; in a Flatpak the portal permissions may be needed (not tested). |
| An action does nothing | Look for the inline `error`/`message` text in the page, then the log file. |

## 8. Accounting problems

| Message (from `AppError::Validation`) | Meaning |
|---------------------------------------|---------|
| unbalanced transaction: total debits … != total credits … | debits ≠ credits |
| only a draft transaction can be posted | already posted/reversed |
| transaction date … does not fall within fiscal period … | no period contains that date; create one (Companies/Settings) |
| cannot post to fiscal period … because it is closed/locked | reopen (Closed → Open) or use another period; Locked is permanent |
| payment amount … exceeds … remaining/open balance | overpayment (or credit note larger than the receivable) rejected |
| only an administrator can … | acting user lacks `users.manage` |
| FOREIGN KEY / "in use" style messages | the record is referenced; deactivate or archive instead |

## 9. Debugging workflow

1. Reproduce on a scratch data directory ([section 6](#6-using-a-throw-away-data-directory)) with `MEMONBOOKS_ENV=development`.
2. Read the last lines of the log; look for the panic message or the `AppError` text.
3. Write the smallest failing test against the service or repository with `Database::open_in_memory()` ([testing-qa.md](testing-qa.md)). Prefer a test in the matching `tests/<area>` target.
4. Fix in the lowest layer that owns the rule (engine/repository, not the view).
5. `cargo check -j 1`, run the relevant test target, then open the screen again.
6. Add a line to `CHANGELOG.md` if behaviour changed.
